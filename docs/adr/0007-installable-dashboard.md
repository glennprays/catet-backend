# Installable dashboard

Capture is WhatsApp-first and the dashboard is a peer capture surface rather than a viewport (ADR-0004), but the review work — Hold Queue, Needs-Review, the calendar, analytics — happens only there, on the phone the user actually holds, behind a URL they have to re-find. So the dashboard is an **installable PWA** on the same origin as its BFF: `src/app/manifest.ts` is served at `/manifest.webmanifest` with `id "/"`, `name`/`short_name` "catet", `scope "/"`, `display "standalone"`, `orientation "portrait"`, `lang "id"`, `theme_color` and `background_color` `#f2f4f7`, three PNG icons (192, 512, 512 maskable) and a 180px `apple-icon.png`. `start_url` is `/?source=pwa`, and an anonymous request to it redirects to `/login` in middleware instead of being rewritten to the marketing page — a home-screen icon must open the app, never a landing page; a signed-in request falls through to Overview. The manifest, `sw.js`, `/icons/*`, `apple-icon` and `/offline` are exempt from the auth matcher.

Installability is the whole of it: an **offline shell, not an offline app**. The worker is hand-written (`public/sw.js`, no workbox or serwist) because it has two jobs — precache the `/offline` page and the app icon at install, cache hashed `/_next/static/` assets on demand. Navigations are always network-first with the offline page as the fallback, and `/api/*`, RSC payloads and cross-origin requests are never intercepted, so authenticated JSON never touches disk. The worker is versioned by build id (`sw.js?v=<id>`); a new one waits and activates only when the user taps "Versi baru tersedia", so a deploy never swaps code under a half-filled form. There is no Web Push — reminders stay the once-a-day WhatsApp digest (ADR-0006) — and no offline data entry, because WhatsApp is already the capture path that works with no connection.

One origin makes the rest cheap. Production is a single origin, `catet.lol`: `/api/*` is the Next BFF and the Go API stays docker-internal (no CORS, no public DNS), so the installed app is same-origin with everything it fetches. Sessions now **slide**: `SessionTTL` is still 30 days, but `RequireAuth` answers any request whose token is at least 7 days old (`auth.RenewAfter`) with an `X-Session-Renew` header carrying a freshly minted JWT, and the BFF re-sets the httpOnly cookie. A device in regular use never meets an expiry, while `users.session_epoch` and "log out everywhere" remain the revocation lever, so the trust model is unchanged. Standalone also brings obligations the dashboard's DESIGN.md owns in detail: iOS status bar `default` (opaque), `viewport-fit=cover` with safe-area insets, no pull-to-refresh, an offline banner above the bottom nav, mutations that fail fast offline with one toast, a revealed amount that re-masks when the installed app is hidden, and phone-first density — the type scale steps up twice below 640px through `--text-*` tokens and controls are 44px below 640px against 32px above.

## Consequences

- The service worker is a deploy artifact with a version contract: `sw.js?v=<build id>` must change on every deploy or the browser keeps the worker it has, and since activation waits for the user's tap, an open client may run a version behind until it accepts the update.
- Nothing authenticated is cached, so "offline" is a branded page and a banner, never stale numbers — and there are no offline writes, so capture stays WhatsApp-only by design.
- iOS gives an installed app its own cookie jar: a user already signed in in Safari signs in once more inside the installed app.
- Renewal makes a response header load-bearing: a BFF that drops `X-Session-Renew` silently returns sessions to a hard 30-day expiry. There is no cap on renewals, by design — revocation is the epoch, not expiry.
- Installability is gated rather than assumed: the manifest, the icons, `sw.js`, the `?source=pwa` redirect and the offline page are covered by the e2e suite, and Lighthouse's installability check is part of the deploy bar.
- `?source=pwa` is only a marker of a home-screen open — it survives into Overview for a signed-in user and must never be read as a filter.
